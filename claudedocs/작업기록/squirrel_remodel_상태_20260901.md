## 모델러 작업 결과 (색 경계 수정)

### 무엇을 어떻게 고쳤는가

**1) 색 경계 — 정점 색(vertex color) 블렌딩으로 교체했다 (차선책 아님, 정공법)**

`assign_materials()` (면 단위 하드 컷오프)를 삭제하고 다음으로 바꿨다.

- `shade_coat(obj, field)` : `field(정점좌표, 정점법선) -> 0~1 연속 스코어`
- `smooth_scalar()` : 메시 엣지를 따라 라플라시안 평균을 4~5회 돌려 스코어를 부드럽게
- `ramp_rgb()` : 스코어를 `FUR_DARK → FUR → FUR_MID → BELLY` 4단 그러데이션으로 보간
- `set_vertex_colors()` : 결과 RGB 를 Color Attribute `Blend`(FLOAT_COLOR, POINT)에 굽는다
- 재질은 **털 재질 하나(`Fur`)로 통합**. Base Color 에 `ShaderNodeVertexColor(layer_name="Blend")`
  를 직접 연결했다. `FurDark` / `Belly` / `Membrane` 재질은 없앴다.

몸통·머리·팔다리·귀·활공막·꼬리 전부 이 방식이다. 체크무늬는 완전히 사라졌다.

**주의: 라플라시안 스무딩은 세게 걸면 안 된다.** 처음에 12~14회(w=0.72) 돌렸더니
스코어가 전체 평균으로 확산돼 모델이 통째로 창백한 흰색이 됐다. 법선 기반 필드는
원래부터 연속이라 스무딩은 노이즈를 다듬는 용도로만 4~5회면 충분하다.

**2) 진짜 "카드보드 박스"는 활공막이 아니라 몸통이었다**

부위별 격리 렌더로 확인했다. 몸통은 스킨 모디파이어로 만들었는데 **스킨의 단면이
사각형**이라 섭디비전 2단계를 걸어도 둥글어지지 않는다. 정면에서는 둥글어 보이지만
옆·위에서 보면 각진 식빵 덩어리다. PD 가 지적한 "각진 판때기"의 정체가 이것이었다.

→ 몸통을 **파라메트릭 구(`torso_shape`)** 로 다시 만들었다. 팔다리는 몸통 메시에서
떼어내 `make_tube` 로 따로 만들고 `arm.L/R`, `leg.L/R` 에 100% 리지드 바인딩했다.
(자동 웨이트가 팔 정점을 흘리는 위험도 같이 사라졌다)

**3) 감기 방향(winding)이 뒤집혀 있었다 — 조용한 버그**

`sphere_verts_faces()` 와 꼬리의 면 감기 순서가 반대라 **구·꼬리의 법선이 안쪽을
향하고 있었다.** 블렌더는 뒷면도 알아서 뒤집어 셰이딩하므로 렌더는 멀쩡해 보였다.
증상은 색으로 드러났다 — `0.5 - 0.58*nz` 카운터셰이딩이 뒤집혀 등이 하얗고 배가
파랬다. 감기 순서를 바로잡고, 재발 방지로 `mesh_signed_volume()` / `check_winding()`
을 빌드에 넣었다(닫힌 메시 42개 전부 양수 확인, 아니면 빌드 실패).

**4) 활공막**
- 앞뒤 끝을 손목/발목이 아니라 **목 옆 · 꼬리 밑동**까지 늘리고 폭을 거의 0 으로
  좁혔다(Catmull-Rom 7 통과점). 앞뒤 테두리도 바깥으로 볼록하게 했다.
- 단면을 직선 보간에서 **2차 베지어**로 바꿔 옆구리에서 수평으로 빠져나오게 했다.
  직선으로 이으면 몸통에서 나오는 자리에 각진 접힘선이 생긴다.
- 부착선을 몸통 **윗 옆구리(z≈0.59)** 로 올렸다. 낮게 붙이니 둥근 몸통에 가려 안 보였다.
- 두께 `sol.thickness` 0.017 → **0.009**. sag 는 그 자리의 폭에 비례(0.22×chord)하게 해서
  좁아지는 앞뒤 끝이 늘어지지 않게 했다.
- 색 대비를 낮췄다(`g = 0.40 - 0.17*nz`). 윗면/아랫면이 몸통 옆구리 색 근처에서만 움직인다.

**5) 꼬리**
- 두께를 폭의 0.6배까지 키워 칼날 → **납작하지만 폭신한 솔**로 바꿨다.
  (`h_ctrl` 최대 0.063 → 0.134), 끝을 뾰족한 바늘이 아니라 뭉툭하게 마감.
- 단면에 각도별 털뭉치 요철(`tuft`)을 넣고 `fur_displace` 진폭 0.019 → 0.030.

**6) 덤으로 고친 것**
- 미리보기 뷰 트랜스폼을 AgX → **Standard** 로. AgX 가 밝고 채도 높은 색을 흰색으로
  밀어버려서 베이스 컬러를 눈으로 판단할 수 없었다. 조명 세기도 낮췄다.
- 털 노멀맵 강도 0.85 → 0.55, 러프니스 변화 폭 0.20 → 0.075.
  UV 섬(island)마다 광택이 달라 보여 머리에 조각보 무늬가 보였다.
- 수염을 한 점에서 부챗살로 뽑던 것을 뿌리를 흩고 아래로 처지게 바꿨다(5가닥, 더 가늘게).
- 머리를 뒤로 0.032 m 당기고 몸통 앞을 늘려 **목의 패인 자국**을 없앴다.

### 정점색이 glTF/Godot 에서 살아남는가 — 확인한 것과 확신 못 하는 것

**확인한 것 (glb 를 직접 파싱해 측정):**
- 털 메시 11개 전부에 `COLOR_0` 이 들어 있다 (`ArmL/R, Body, EarL/R, Head, LegL/R, PatagiumL/R, Tail`)
- 타입은 VEC3 / componentType 5126(float) / normalized=false
- 값이 구운 그대로다 — min `[0.275, 0.495, 0.715]`(FUR_DARK), max `[0.955, 0.975, 1.0]`(BELLY).
  감마 변환이나 클리핑 없음
- `Fur` 머티리얼의 `baseColorFactor` 가 없다(=흰색 기본값)이므로 Godot 에서
  `albedo × 정점색` 이 곧 의도한 색이 된다

**확신 못 하는 것:**
1. Godot glTF 임포터가 `vertex_color_use_as_albedo` 를 자동으로 켜 주는지 **실제 엔진에서
   확인하지 않았다.** 안 켜지면 모델 전체가 흰색 단색으로 보인다. 코더가 임포트 후
   `StandardMaterial3D.vertex_color_use_as_albedo` 를 한 번 봐 주면 확실하다.
2. `COLOR_0` 이 VEC4 가 아니라 **VEC3** 다. 스펙상 허용이지만 임포터 구현에 따라
   예민할 수 있다.
3. `KHR_materials_sheen` / `KHR_materials_specular` / `KHR_materials_ior` 가 확장으로
   나가는데 **Godot 은 sheen 을 읽지 않는다.** 블렌더 미리보기의 부드러운 털 산란은
   Godot 에서 재현되지 않는다. 실제 화면 질감은 노멀맵 + 러프니스 텍스처가 담당한다.
4. 모든 재질이 `doubleSided: true` 로 나간다. 후면 컬링이 꺼지므로 오버드로가 늘지만
   법선 뒤집힘 사고는 안 난다.

### 사진과 비교했을 때 아직 부족한 점 (숨기지 않음)

1. **털이 진짜 털이 아니다.** 사진의 하늘다람쥐는 윤곽 자체가 털로 부스스한데,
   이 모델은 매끈한 표면 + 노멀맵이다. 실루엣은 여전히 깔끔한 곡선이다.
   파티클 헤어는 glTF 로 안 나가므로 지오메트리로 털을 심지 않는 한 한계다.
2. **기본 자세가 활공 자세라 몸이 길어 보인다.** 사진의 앉은 하늘다람쥐는 거의 공인데,
   이 모델은 옆에서 보면 수달/족제비에 가깝다. 접은 자세(`_pose.png`)가 사진에 더 가깝지만
   그래도 사진만큼 동그랗지는 않다.
3. **활공막이 접힌 자세에서 옆구리에 겹침 선이 보인다.** 자동 웨이트로 접히다 보니
   막이 몸통을 뚫고 겹치는 구간이 있다. 게임 카메라 거리에서는 잘 안 보이지만 있다.
4. **활공막 앞 테두리에 술(fringe) 때문에 생긴 톱니 자국**이 위에서 보면 조금 거슬린다.
   털 가장자리로 읽히기도 하고 메시 오류로 보이기도 한다.
5. **꼬리가 사진보다 여전히 매끈하다.** 폭신해지긴 했지만 사진의 깃털 같은 낱털 느낌은
   아니고 "폭신한 소시지" 쪽이다.
6. **귀가 사진보다 크고 도드라진다.** 사진의 귀는 머리에 거의 파묻혀 있다.
7. **머리에 UV 이음매가 아주 옅게 한 줄 남아 있다.** 스마트 UV 전개 때문인데,
   구를 파라메트릭으로 만드니 해석적 UV 를 직접 붙이면 완전히 없앨 수 있다. 이번엔 안 했다.
8. **활공막 색이 몸통과 너무 비슷해져서** 활공 시 막이 어디까지인지 실루엣으로만 읽힌다.
   PD 지시대로 대비를 낮춘 결과인데, 게임에서 활공이 핵심이라면 조금 되돌리는 편이
   나을 수도 있다. 판단 필요.

### 최종 값 (`blender/build_flying_squirrel.py` 66~80줄)

색상각(hue)을 **정확히** 보존하려고, 색을 자기 자신의 휘도(회색)를 향해 선형으로
당기는 `_desat(c, k)` 헬퍼를 넣었다. R-G / G-B / B-R 차이가 전부 같은 비율로 줄어들므로
HSV 색상각은 그대로고 채도만 k 배가 된다. 하늘색 명세를 잃을 위험 없이 채도만 만진다.

```python
FUR_HUE      = (0.45, 0.72, 0.92)    # 원래의 만화적 하늘색 — 채도 51%
FUR_DARK_HUE = (0.275, 0.495, 0.715)
COAT_SAT = 0.58     # 채도 배율
COAT_VAL = 0.92     # 밝기 배율
FUR      = _desat(FUR_HUE, COAT_SAT)      * COAT_VAL
FUR_DARK = _desat(FUR_DARK_HUE, COAT_SAT) * COAT_VAL
BELLY    = (0.885, 0.905, 0.930)
FUR_MID  = _mix(FUR, BELLY, 0.42)
```

전개된 실제 값 (선형 RGB / HSV):

| 상수 | 선형 RGB | H | S | V |
|---|---|---|---|---|
| `FUR` | (0.5017, 0.6458, 0.7525) | 205.5° | **33.3%** (이전 51.1%) | 75.3% |
| `FUR_DARK` | (0.3261, 0.4435, 0.5609) | 210.0° | 41.9% | 56.1% |
| `FUR_MID` | (0.6627, 0.7547, 0.8271) | 206.4° | 19.9% | 82.7% |
| `BELLY` | (0.8850, 0.9050, 0.9300) | 213.3° | 4.8% | 93.0% |

`COAT_STOPS` 의 등→배 순서(`FUR_DARK → FUR → FUR_MID → BELLY`)와 위치는 손대지 않았다.
그러데이션 관계는 그대로다.

### 판단 근거

1. **PD 어림값(채도 약 30%)을 목표로 두되 렌더로 검증했다.** 0.55 / 0.68 / 0.80 세 값으로
   각각 빌드해 미리보기를 찍고, 배경을 행별 중앙값으로 마스킹해 모델 픽셀만의 평균
   sRGB 채도를 쟀다.

   | COAT_SAT | 화면 평균 S |
   |---|---|
   | 1.0 (조정 전) | 11.83% |
   | 0.80 | 10.04% |
   | 0.68 | 8.97% |
   | 0.55 | 7.79% |

   0.58 을 골랐다. 베이스 컬러 채도 33% 로 PD 어림값 범위 안이고, 화면상으로는
   조정 전 대비 채도가 약 1/3 줄어 "쨍한 사탕색"이 사라진다. 배경(회색)의 화면 채도가
   4.5% 라서, 화면 8% 대는 아직 회색과 확실히 구분되는 파랑이다 — 하늘색 정체성은 남았다.

2. **`BELLY` 를 순백(0.955,0.975,1.0)에서 (0.885,0.905,0.930)으로 내렸다.** 원래 값은
   조명에서 완전히 날아가 흰 플라스틱으로 보였다. 값만 내리고 색상각은 유지.

3. **`COAT_VAL = 0.92`.** 채도만 낮추면 "창백한 물빛"이 되기 쉬워서 밝기를 8% 내렸다.
   가라앉은 하늘색 쪽으로 붙인다.

- 이 미리보기 조명이 꽤 밝다(모델 픽셀 평균 V 88%). 그래서 베이스 컬러를 아무리 만져도
  화면 채도는 크게 안 움직인다(1.0 → 0.55 로 절반 가까이 낮춰도 화면상 11.8% → 7.8%).
  즉 **사용자가 본 "플라스틱" 인상에는 미리보기 조명 몫도 있다.** 이번엔 지시대로

- 채도를 여기서 더 내리면 배경 회색과 구분이 흐려진다. 0.58 이 안전한 하한에 가깝다.

## 모델러 작업 결과 (활공막 대비 복원)

### 무엇을 했는가

구조는 그대로 뒀다 — 여전히 `Fur` 재질 하나 + 정점색(`Blend`) 그러데이션이다.
막에만 **전용 그러데이션 표(`MEM_STOPS`)와 전용 스코어 함수**를 줬다.

**1) 막 가장자리 색 `MEM_EDGE` 를 새로 정의**

```python
MEM_EDGE = tuple(FUR_DARK[i] * 0.62 for i in range(3))   # (0.2022, 0.2750, 0.3478)
```
균일 배율이라 **색상각은 FUR_DARK 와 완전히 같고 명도만 내려간다**(sRGB V 62.4%).
사진 속 하늘다람쥐도 막의 테두리만 뚜렷하게 진하다 — 그 선이 날개 윤곽을 그려 준다.

**2) 막 전용 그러데이션**

```python
MEM_STOPS = [(0.00, MEM_EDGE), (0.30, FUR_DARK), (0.62, FUR), (0.86, FUR_MID), (1.00, BELLY)]
```
몸통 표(`COAT_STOPS`) 앞에 진한 단을 하나 덧댄 것이다. 나머지 단은 몸통과 같은 색이라
**부착선 쪽은 몸통 색 그대로 이어지고**, 바깥으로 갈수록만 가라앉는다.

**3) 정점 속성 `MemU` — "부착선 0 → 바깥 테두리 1"**

색을 칠하려면 굽고 난 뒤에도 u 를 알아야 하는데, 좌표에서 되계산하면 앞뒤 끝처럼
폭이 0 에 가까운 데서 무너진다. 그래서 **솔리디파이 전에 정점 FLOAT 속성으로 심고
구운 뒤 읽는다.** 살아남는지는 추측하지 않고 `read_float_attr()` 에서 검사한다
(없거나 상수면 빌드 실패). 실측으로 확인함:

```
PatagiumL: 정점 1110  u min=0.000 max=1.000
   윗면 594개 u평균=0.503 / 아랫면 516개 u평균=0.497   ← 솔리디파이 복제면에도 정상 전파
   u 0.00~0.10 : |x|평균=0.138 (부착선)
   u 0.90~1.01 : |x|평균=0.419 (바깥 테두리)
```

**4) 스코어 함수** (각진 경계가 안 생기게 전부 smoothstep)

```python
core = sstep(u, 0.00, 0.45)      # 부착선에서 멀어지며 서서히 가라앉음
edge = sstep(u, 0.55, 0.90)      # 바깥 테두리 띠
g = 0.70 - 0.24 * nz  -  0.18*core  -  0.52*edge  +  노이즈*0.10
```
라플라시안 스무딩은 5회(w 0.60) → **3회(w 0.45)** 로 줄였다. 세게 돌리면 테두리 띠가
안쪽으로 번져 없어진다.

### 수치로 본 대비 (glb 의 `COLOR_0` 을 직접 파싱해 잰 값, sRGB 명도 V)

| 메시 | 평균 V | 5~95퍼센타일 V |
|---|---|---|
| BodyMesh | 88.3% | 77~97% |
| Patagium (조정 전) | 86.7% | **84~90%** |
| Patagium (조정 후) | **80.0%** | **62~91%** |

조정 전 막은 84~90% 로 거의 단색이라 몸통(88.3%)과 구분이 안 됐다.
지금은 테두리가 62% 까지 내려가 몸통과 26포인트 차이가 난다.

### 각지지 않았는지 확인

- 모든 전이가 smoothstep(3t²−2t³)이고, 부착선 쪽 45% 구간에 걸쳐 서서히 변한다.
  선을 그은 게 아니라 그러데이션이다.
- 부착선(u=0)에서는 색이 몸통 옆구리와 같으므로 **몸에서 이어져 나온 것으로 보인다.**
  "카드보드 상자" 시절처럼 몸통과 따로 붙인 판으로 보이지 않는다.
- 접은 자세(`flying_squirrel_pose.png`)에서도 옆구리의 접힌 주름으로 자연스럽게 읽힌다.
